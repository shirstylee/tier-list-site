# 🎮 TIER LIST

Стильное веб-приложение для создания и сохранения игровых тир-листов. Игры загружаются из [RAWG Video Games Database](https://rawg.io/apidocs), а пользовательские данные хранятся локально в браузере.

## ✨ Возможности

- создание нескольких тир-листов;
- добавление игр из каталога RAWG;
- поиск по названию и фильтры по году, жанру, платформе и рейтингу;
- перетаскивание игр между рангами и изменение порядка внутри ранга;
- удаление игр и собственные названия рангов;
- выбор любого цвета, дублирование и изменение порядка рангов;
- готовые шаблоны рангов;
- отмена и повтор действий;
- автоматическое и ручное сохранение;
- экспорт тир-листа в PNG;
- импорт и экспорт локальных данных;
- редактирование никнейма и аватарки;
- статистика профиля;
- адаптивный интерфейс и поддержка перетаскивания на телефоне;
- установка сайта как PWA-приложения.

## 🧰 Технологии

- React 19;
- Vite 7;
- Tailwind CSS 4;
- Phosphor Icons;
- RAWG API;
- pnpm;
- Node.js: серверный API и публикация сайта;
- Docker (необязательно).

## ✅ Требования

Перед запуском установите:

- [Node.js](https://nodejs.org/) версии 22.13 или новее; для релиза рекомендуется Node.js 24 LTS;
- [pnpm](https://pnpm.io/installation).

Проверить установку можно командами:

```powershell
node --version
pnpm --version
```

## 🚀 Установка и запуск

1. Откройте папку проекта в VS Code.
2. Откройте терминал через `Терминал → Создать терминал`.
3. Установите зависимости:

```powershell
pnpm install
```

4. Создайте локальный файл окружения:

```powershell
Copy-Item .env.example .env
```

5. Запустите проект:

```powershell
pnpm dev
```

6. Откройте адрес, показанный в терминале. Обычно это:

```text
http://localhost:5173
```

## 🔑 Настройка RAWG API

1. Получите API-ключ на [rawg.io/apidocs](https://rawg.io/apidocs).
2. Откройте файл `.env`.
3. Вставьте ключ после знака `=`:

```env
RAWG_API_KEY=ваш_ключ_rawg
```

4. После изменения `.env` перезапустите сервер разработки.

Файл `.env` добавлен в `.gitignore` и не должен попадать на GitHub. Файл `.env.example` содержит только пример и безопасно публикуется.

Ключ используется только сервером. Браузер отправляет запросы на `/api/rawg/…` без ключа. Не добавляйте префикс `VITE_`: такие переменные попадают в публичный JavaScript. При запуске `pnpm dev` и `pnpm preview` API работает через серверную часть конфигурации Vite; для общего доступа запускайте `pnpm start`.

Если RAWG временно недоступен, приложение автоматически использует встроенный демонстрационный каталог.

## 📱 Запуск на телефоне

Компьютер и телефон должны находиться в одной локальной сети. Частоты Wi-Fi 2,4 и 5 ГГц могут отличаться — важно, чтобы оба устройства были подключены к одному роутеру и видели друг друга.

Запустите сервер с доступом из локальной сети:

```powershell
pnpm dev --host 0.0.0.0
```

В терминале появится адрес `Network`, например:

```text
http://192.168.1.25:5173
```

Откройте этот адрес в браузере телефона. Если страница недоступна, разрешите Node.js доступ к частным сетям в брандмауэре Windows.

## 📦 Production-сборка

Создать оптимизированную сборку:

```powershell
pnpm build
```

Проверить её локально:

```powershell
pnpm preview
```

Готовые файлы будут созданы в папке `dist`.

## 🌍 Публичный релиз

Подробная инструкция: [docs/RELEASE.md](./docs/RELEASE.md).

Хостинг должен поддерживать Node.js или Docker: статическая публикация только папки `dist` не запускает серверный RAWG API. Сайт рассчитан на корень домена (`https://example.com/`). GitHub Pages без отдельного API для этого варианта не подходит.

Для хостинга с Node.js:

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm test
pnpm check:release
pnpm start
```

Команда сборки на хостинге: `pnpm install --frozen-lockfile && pnpm build`. Команда запуска: `pnpm start`. В настройках хостинга добавьте секрет `RAWG_API_KEY`. Используйте HTTPS; `PORT` обычно задаёт хостинг. `/api/health` возвращает состояние сервера и факт настройки RAWG без значения ключа.

Для локальной проверки production-версии откройте `http://localhost:3000` после `pnpm start`.

## 💾 Где хранятся данные

Тир-листы, профиль и настройки сохраняются в `localStorage` текущего браузера. Они не отправляются на сервер и не синхронизируются между устройствами. Для резервного копирования используйте экспорт данных в профиле.

Очистка данных сайта в браузере удалит локальные тир-листы, если они не были предварительно экспортированы. `localhost` и публичный домен имеют разные хранилища: экспортируйте данные в профиле локального сайта и импортируйте их на публичном.

```text

src/hooks/          Пользовательские React-хуки
src/lib/            RAWG API, экспорт PNG и вспомогательная логика

src/App.jsx         Основная логика приложения

tests/              Проверки API и резервных копий

```
