# 🚀 Публикация TIER LIST

## 🔑 Где находится RAWG-ключ

- На компьютере: `.env` в корне проекта, переменная `RAWG_API_KEY`.
- На хостинге: секрет/переменная окружения `RAWG_API_KEY` в панели сервиса.
- `.env.example` содержит пустое поле для ключа. Его можно хранить в GitHub.
- `.env` и все `.env.*`, кроме `.env.example`, исключены из Git и Docker-контекста.
- Сервер добавляет ключ только при обращении к `https://api.rawg.io/api/`. Браузер обращается к `/api/rawg/…`. Сервер не возвращает upstream-ссылки пагинации, в которых RAWG мог бы передать ключ.

Старая переменная `VITE_RAWG_API_KEY` перенесена в `RAWG_API_KEY`. Значение не менялось. Vite встраивает переменные с префиксом `VITE_` в клиентский JavaScript: [официальная документация](https://vite.dev/guide/env-and-mode.html#env-variables). Если предыдущая сборка публиковалась или отправлялась другим людям, замените ключ в аккаунте RAWG и обновите секрет на хостинге. Переименование переменной не отзывает старый ключ.

Не загружайте `.env`, исходный проект или старую сборку вручную в общедоступную папку веб-сервера. Production-сервер раздаёт только `dist` и разрешённые API-маршруты. `pnpm check:release` проверяет известные локальные ключи, но не заменяет проверку всех других секретов, которые вы самостоятельно добавите.

## 🌍 Хостинг с Node.js

1. Отправьте подготовленные изменения проекта в GitHub.
2. Подключите репозиторий к сервису, который запускает постоянный Node.js-процесс, либо к своему серверу.
3. Используйте Node.js 24 LTS и pnpm, указанный в `package.json`.
4. Команда сборки: `pnpm install --frozen-lockfile && pnpm build`.
5. Команда запуска: `pnpm start`.
6. В панели добавьте `RAWG_API_KEY`. `HOST=0.0.0.0`; порт задаётся переменной `PORT` (по умолчанию 3000).
7. Подключите HTTPS и домен. Сайт должен открываться в корне домена, а `/api/` — на том же домене.
8. Проверьте `/api/health`: ожидается `{"ok":true,"rawgConfigured":true}`. Это подтверждает настройку переменной, а не действительность ключа. Действительность проверяется поиском игр.

`pnpm dev` и `pnpm preview` предназначены для локальной разработки и проверки. Production запускается командой `pnpm start`. GitHub Pages раздаёт статические файлы и не выполняет этот Node.js API. Для serverless-хостинга понадобится адаптер серверных функций; готовый вариант этого проекта — Node.js или Docker.

## 🐳 Docker

```powershell
docker build -t tier-list .
docker run --rm -p 3000:3000 --env-file .env tier-list
```

Откройте `http://localhost:3000`. Ключ передаётся во время запуска контейнера и не включается в образ. В production задавайте его секретом платформы и используйте HTTPS перед контейнером. Финальный образ содержит только Node.js, сервер и `dist`; `node_modules` в production не требуются.

## 🛡️ Ограничения публичного API

Сервер разрешает только поиск игр и информацию об игре; произвольные адреса и пользовательский параметр `key` отклоняются. Есть таймаут, кэш, объединение одинаковых одновременных запросов, ограничение параллелизма, 60 запросов в минуту на клиента и 300 в минуту на процесс.

По умолчанию IP берётся из соединения. За доверенным reverse proxy можно включить `TRUST_PROXY=1`, только если он заменяет `X-Forwarded-For`, а прямой доступ к Node.js закрыт. Иначе заголовок можно подделать. Без настройки за прокси все пользователи могут разделять один IP-лимит.

Кэш и лимиты хранятся в памяти одного процесса. Для нескольких экземпляров и большой аудитории нужен общий кэш/лимитер и ограничение запросов на уровне платформы. Текущие лимиты уменьшают повторные запросы, но не гарантируют соблюдение месячной квоты RAWG при любой нагрузке. Следите за расходом в аккаунте RAWG и настройте ограничения хостинга.

## 💾 Пользовательские данные

Аккаунтов и серверной базы пользователей нет. Профиль, тир-листы и история поиска хранятся в браузере. Данные не синхронизируются между устройствами. При смене домена или переходе с `localhost` нужен экспорт и импорт через профиль. Не очищайте данные браузера без резервной копии.

Поисковый запрос отправляется серверу приложения и RAWG; изображения загружаются с RAWG/Steam CDN. Хостинг может хранить стандартные журналы запросов. Секрет не логируется приложением. Автосохранение показывает ошибку, если браузер запрещает хранение или место закончилось.

## 📱 PWA и обновления

Установка доступна по HTTPS (или на `localhost`). На телефоне локальный адрес по HTTP позволяет проверить интерфейс, но не гарантирует установку PWA. Добавлены PNG-иконки 192×192 и 512×512 и Apple Touch Icon.

Service worker не кэширует `/api/`, не сохраняет ошибочные ответы и возвращает HTML только для навигации, а не для пропавших JS/CSS-файлов. Для новой версии активируйте обновлённый worker после закрытия всех вкладок сайта. При изменении стратегии кэша увеличивайте `CACHE_NAME` в `public/sw.js`. Полный офлайн-поиск RAWG не предусмотрен: при отсутствии связи используется ограниченный демо-каталог.

## ✅ Проверка перед каждой публикацией

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm test
pnpm check:release
pnpm audit --audit-level=high
pnpm start
```

Затем проверьте в браузере: создание списка, поиск игры, перетаскивание между рангами и внутри ранга, обновление страницы, экспорт/импорт JSON, PNG-экспорт и мобильный интерфейс. Проверяйте вкладку Network: запросы идут на `/api/rawg/…`, параметра `key` в браузере нет. Серверный `/api/health` и сообщения об ошибках не должны раскрывать ключ.

GitHub Actions выполняет сборку, тесты API/данных, проверку публичных файлов и аудит зависимостей без доступа к вашему RAWG-ключу. Тесты API используют поддельный ключ и не тратят квоту RAWG.

## 🎮 Условия RAWG

Активная ссылка на RAWG добавлена в футер сайта и в информацию об игре, указание источника — в PNG. Перед публикацией проверьте ограничения вашего тарифа и разрешённое использование данных: [RAWG API](https://rawg.io/apidocs), [условия API](https://rawg.io/tos_api). Отдельное разрешение на использование изображений и товарных знаков не выдаётся этим проектом.
